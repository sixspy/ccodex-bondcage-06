# 出金绑票命运说明（当日锁死）

- 锁死日期：2026-11-22（当日定稿，之后不得改写口径）
- 适用仓：保证金笼（本仓 `/workspace`，库文件路径 `data/app.db` 不变）
- 约束来源：README 明令「主链路不是『占位→确认入册』」，故乙路径（待绑票占位→晋升入册）在本仓被禁止。

## 一、唯一选定口径：甲路径（缺票零写入）

出金（解笼拨付 `/api/releases`）**强制绑票**：请求必须携带非空 `attest_ticket_no`（核验票号），且该票号必须真实存在、属于本笼、笼代一致、结论为「通过」。

缺票（字段缺失/空白字符串）或票号无效（不存在、属他笼、笼代不符、非通过票）时，**只允许甲路径一种处理**：

1. 正式拨付册 `releases` **零行写入**——不得 INSERT 任何状态的拨付行（无「待绑票/占位/待晋升」行，无影子行）。
2. 笼可用 `cages.available` 与笼状态**零改**。
3. 账户 `bond_accounts.balance` 与 `bond_accounts.frozen` **零改**（不新增冻结、不占位冻结、不解冻）。
4. 仅在审计册 `audit_trail` 记一条拒写：
   - 缺票动作 `release_reject_no_ticket`；
   - 票号无效动作 `release_reject_bad_ticket`；
   - 载荷含 cage_id、cage_code、cage_generation、提交的票号原值、金额、拒写原因。
   - 该审计行必须独立提交落库，然后才抛出 4xx；不得随业务回滚一起消失。

## 二、禁止混用与第三路（偏航即拒写）

- 禁止乙路径的一切形态：不得新建占位表/占位行、不得「先冻结等额可用、票齐再晋升入册」、不得设置超时作废流程。本仓不存在、也不得新增任何待绑票占位状态。
- 禁止任何第三路（如默认票、补票后写、前台只拦不校验等）。
- 混用必然导致两类假账，均视为**绑票偏航**：
  1. 缺票行竟进入正式拨付册 `releases`；
  2. 占位把资金冻住，对账却仍把该额当可用亮绿灯。
- 出现偏航：写口必须拒写（不产生业务行），并按上节审计动作留痕。禁止只改解笼页票号提示而写口不校验。

## 三、同笼并发：抢笼锁，后到只留争用痕

- 两人（双令牌）对同一笼出金，以 `cage:{cage_id}` 抢笼锁，先到者执行业务，后到者不得写任何业务数据。
- 后到者只在 `contention_log` 留一条争用痕（动作「争用」），该痕必须独立提交落库，随后返回 409；不得随异常回滚消失。
- 本节约束与第一节命运取舍**分开验收**：争用逻辑不改变缺票口径，缺票口径也不豁免争用登记。

## 四、五页同源

解笼页、核验页、对账页、账户页、审计页的票号与冻结数必须同源（同一 SQLite 母库 `data/app.db`，同一套服务读模型），禁止页间各算各的：

- 票号源头唯一：`attestations.ticket_no`（核验通过时生成，全表唯一）；拨付册 `releases.attest_ticket_no` 只能引用已存在的通过票。
- 冻结数源头唯一：账户 `bond_accounts.frozen` 恒等于活笼（已冻结/核验通过/核验违约/部分解笼/部分罚没）`cages.available` 合计；拒写不改变任何一侧。
- 正式拨付册每一行都必须带非空票号；对账、审计展示的票号与拨付行逐行对齐。

## 五、偏离处置

任何代码改动若与本说明冲突（出现占位、缺票入册、冻结与对账绿灯拧着、争用痕回滚丢失、票号跨页对不上），记为「绑票偏航」，写口拒写、测试不得放行。本说明只允许随新的、明确 supersede 文档修订；当日（2026-11-22）锁死。
